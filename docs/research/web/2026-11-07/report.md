## 実装した動作

ユーザー指定の操作は、**「収集ボタン→JRAから取得→DBへ保管」「通常分析→保存済みDB」**。JRAへ毎回検索しに行く仕組みではない。通常の検索、条件変更、画面再読込、保存条件の読込、CSV出力はDBだけを使う。収集開始と中断後の再開は本人の明示操作から行う。

機能1に、本人ログイン・初回のブラウザでのパスワード設定、レース/期間/条件指定、AND/項目内OR・範囲・三値判定、分類別比較、勝率/連対率/3着以内率/複勝的中率・単複実績回収率、分母、条件値を開ける出走明細、条件保存・保存時点の再現・CSVを実装した。性齢を分離した14項目は従来13条件に対応する。今回の出走馬を必要とせず、機能2の画面/APIは追加していない。

Flask＋Gunicorn、SQLAlchemy＋PostgreSQL。原本gzip・SHA重複排除・取得メタデータ・訂正前を残す解析版・年度一覧の確認範囲・保存条件・取得ジョブの計画/カーソルをDBへ保存する。一時ファイルがなくなってもDBから原本を復元する。120秒の排他リース、直列2秒間隔、403/429停止、成功版保持を維持する。通常検索がHTTP取得を呼んだら失敗するテストで分離を確認した。

## JRA接続と系列・払戻の確認

この環境のHTTPSはCONNECT 200、TLS証明書検証成功、JRA HTTP 200。制限やプロキシ設定を変更せずに確認・取得した。外部の配備先から接続できるかはまだ検証していない。

2016〜2025年の年度一覧1,291開催を、明示的な133系列へ照合した。2025年の名称再利用を年別に分け、府中牝馬S/アイルランドT、マーメイドS/府中牝馬S、愛知杯/小倉牝馬S、京都牝馬S/愛知杯、東海S/プロキオンS等をJRA公式沿革で確認した。未登録の名称は部分一致で推測せず停止する。JRA主催のJpnと未格付け平地重賞を含め、障害は除く。[一覧・沿革の出典](catalog_validation.json) と [対応表](../../../../src/keiba_acquisition/data/series_registry.json) を参照。

払戻は券種ごとに公式領域・対象馬番/金額・確定着順・解析値を照合する。払戻未確認は不明のままにし、不的中0円へ変換しない。公式の明示返還と取消を分け、発売時の複勝対象数が不明な例は断定しない。

実原本の例は、2024有馬記念の取消、2021チューリップ賞の1着同着、2021サウジアラビアRCの7頭/複勝2着払い、2020高松宮記念の降着、2026-11-01東京4Rと2024-12-15中山5Rの明示返還。6例で認識した単複の検査エラーは0。これをJRA全形式の保証とはしない。[出典・検査結果](settlement_cases.json) にURL・取得日時・SHAを保存した。

## 保存・復元と容量

PostgreSQL 17の内部検証DBを `pg_dump` し、別の空DBへ `pg_restore`。データ版、159出走、全集計値と原本301件のSHAを照合した。ダンプ4,800,604 bytes。クラウドの定期バックアップを設定したものではない。

追加収集後は取得イベント327件・異なる原本325件、gzip原本4,318,344 bytes、DB全体約15.3MB（検証時点）。10開催の最新ポインタは10件、訂正前/再解析のスナップショットは別保持。重複取り込みで出走数は増えない。これは全平地重賞の容量推定ではない。

容量停止の試験は、新規原本だけを拒否し、以前の原本・解析版・保存条件を維持できた。再接続後も固定した取得計画とカーソルを復元し、模擬HTTP 429で停止した開催から再開して、成功済みを二重計上しないことを検証した。
