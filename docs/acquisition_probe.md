# JRA公式データの自動取得検証ツール

更新：2026-11-05（日本時間）。ユーザー指定により、手作業での転記を必要としない自動取得の成立を、採用継続の条件とする。

## 現在の結果

PythonのCLI `jra-collect` を作成した。合成HTMLによる44件の自動テストと静的チェックが通過している。一方、11月5日の実通信は最初の年度一覧でプロキシ接続に失敗し、取得原本0件だった。JRAの応答本文には到達しておらず、現行HTMLへの解析適合・取得所要時間・方式の実現可否は未判定。

[実行記録JSON](research/samples/jra_acquisition_attempt_20261105.json) に失敗箇所と計測値を保存した。通信失敗までの時間を、収集の処理時間の見積もりには使わない。環境の許可対象にJRAドメインが含まれていないことも確認した。設定ファイルの書き換えや別経路による接続制限の回避は行わない。

その後の [接続原因の切り分け](research/network_diagnostics/2026-11-05/report.md) で、プロキシのCONNECT応答が403、本文が `Domain forbidden` であることを確認した。JRAとのTLS接続・HTTP応答には未到達。新タスク向けの現在地は [引き継ぎ資料](../HANDOFF.md) を参照。

このツールは作業1の技術検証用。分析本体・DB・検索画面・期待値計算はまだ実装していない。テスト用HTMLは [合成フィクスチャ](../tests/fixtures/README.md) であり、公式原本の代用として取得済み件数に数えない。

## 自動で行う処理

1. 指定年度の公式重賞一覧から、指定レース名に一致する結果リンクを抽出する。
2. リンク先の結果を取得し、出走馬・着順・枠・人気・通過順位・単複払戻等を抽出する。画像の代替文字も読む。
3. 馬情報へのリンクがあれば、指定頭数まで取得し、父と対象レース以前の直近実出走を抽出する。取消・除外を前走にせず、後日の走歴も使わない。
4. 原本・取得日時・SHA-256・要求URL・最終応答URLを保存する。過去の保存原本は次回から再利用し、通信せず再解析できる。
5. 出馬表の入口URLを指定した場合、出馬表と単複オッズへのリンクをたどる。候補を一意に選べない場合は停止し、別レースや別券種を推測で選ばない。今回データは毎回再取得する。
6. 成功・不足・未公表・未発売・接続失敗を分け、件数・通信回数・受信量・全体経過時間をJSONに記録する。

HTTP要求は直列、既定の最小間隔は2秒、タイムアウトは15秒。一時的な接続失敗・5xxは最大1回だけ再試行する。403・429ではジョブを停止する。JRA公式内の対象HTMLだけを取得し、PDF/OCR・他社補完は使わない。

通常リンクと `doAction` の文字列引数を読み取り、公開URLへのGET要求として取得する。任意のJavaScript実行やブラウザ自動操作は含まない。実際の画面でフォーム送信・追加セッション処理等が必要かは原本取得後の検証事項。

## PCでのセットアップ

Python 3.12以降を使用し、リポジトリのルートで実行する。依存は [pyproject.toml](../pyproject.toml) と [検証時の固定版](../requirements-dev.lock) に記載。

```console
python -m venv .venv
```

Windows（PowerShell）：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock -e .
.\.venv\Scripts\python.exe -m keiba_acquisition.cli --years 2016,2021,2025
```

macOS / Linux：

```bash
.venv/bin/python -m pip install -r requirements-dev.lock -e .
.venv/bin/python -m keiba_acquisition.cli --years 2016,2021,2025
```

どちらも既定ではアルゼンチン共和国杯を各年度1件、各レースの先頭2頭の馬情報を検証する。データの書き写しや各年の結果URLの手入力は不要。以降の例の `jra-collect` は仮想環境を有効化して実行するか、上記の `python -m keiba_acquisition.cli` に置き換える。

## 検証の広げ方

同じレースの10年度分へ広げる例：

```console
jra-collect --years 2016:2025 --profiles-per-race 18
```

これは同一レース系列の10年度の確認であり、全重賞10年分の網羅性を保証しない。レース名の部分一致は `--race-name`、年度ごとの結果取得上限は `--limit-per-year`、馬情報の取得上限は `--profiles-per-race` で指定できる。原本が安定して取れることと必要項目の充足を確認してから、対象区分全体へ広げる。

指定した今回レースも検証する例：

```console
jra-collect --years 2016,2021,2025 --upcoming-url "https://www.jra.go.jp/keiba/race/101/syutsuba.html"
```

入口は公式が掲載する対象レースのURLを指定する。特定のレースに固定した収集方式ではない。出馬表・単複オッズへの導線を一意に選べない場合は、対象画面のURLを `--upcoming-url`・`--odds-url` へ直接指定して少量検証できる。データ本文の転記は行わない。公開前・発売前のページは成功した出走表・オッズとして数えない。

年度一覧を経由せず、既知の公式結果を単独検証する例：

```console
jra-collect --result-url "https://www.jra.go.jp/JRADB/accessS.html?CNAME=pw01sde1005200605021120061105%2FC3"
```

過去原本も取り直す場合は `--refresh-history` を付ける。通常の再実行では保存原本のハッシュを検査して再利用する。

## 出力と終了コード

既定の保存先は `work/acquisition/`。`--output` で変更できる。

| 出力 | 内容 |
| --- | --- |
| `raw/*.html` / `raw/*.json` | 原本と取得メタデータ。正常なHTML応答のみ保存 |
| `parsed/*.json` | 抽出値、欠損一覧、取得根拠。レース日ごとの前走選択を区別 |
| `reports/*.json` | 実行ごとの履歴 |
| `latest_report.json` | 直近実行の状態・件数・時間・失敗理由 |

| 終了コード | 意味 |
| --- | --- |
| 0 | `sample_passed`。指定した少量サンプルの現行検査を通過しただけで、全件・本体機能の完成ではない |
| 2 | 不足・未公表・未発売・形式不一致・取得失敗等。レポートで理由を確認 |
| 3 | `blocked_environment`。プロキシ接続で失敗し、取得方式の成否は未判定 |

原本とDBはGit管理しない。共有する確認記録はメタデータだけとし、原本や全データをリポジトリへ転載しない。

## 採用継続を判定する条件

- 古い年・中間年・近年で、公式原本から必要な結果・払戻・馬情報を自動で取得できる。
- 馬ID・対象レースの識別、前走参照、年代差、欠損と取消等を実原本で照合できる。
- 今回の出馬表と発売中単複オッズを取得し、対象レース・提供時刻・再取得による更新を実データで照合できる。
- 少量検証から同系列10年度・全対象区分へ拡大し、対象件数、欠損率、初回取得時間、差分更新と保守の負担を実測できる。

既存の保存版ページで馬へのリンクや単勝確定オッズがない場合は、不足として記録する。現在の抽出処理は、脚質の分類、全レース系列の対応付け、返還処理、前走クラスの確定までを完成させたものではない。少量検査の合格を全要件の実現証明として扱わない。

公式内の別画面で少ない追加処理により補えるかを検証し、自動取得が成立しない、または大量の手作業・PDF解析・維持負担が必要なら、作業2以降の本体実装へ進まず取得方式の比較へ戻る。方式の変更は理由とコストを提示してユーザーが選択する。今回の環境側の遮断だけで、JRA側が自動取得不能と判断しない。

接続できた後の見積もりでは、原本保存済みの再実行と初回通信を分け、結果ページ・馬情報等の必要ページ数と待機時間を含める。現段階で全件収集時間は未測定。
